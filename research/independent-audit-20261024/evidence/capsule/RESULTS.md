Candidate A source requires an explicit main command because OpenShell replaces image ENTRYPOINT. Its current Linux isolation wrapper requires root, while live OpenShell policy rejects root workload IDs. That is a decisive incompatibility for this path unless Jackin redesigns session isolation or OpenShell changes its supported policy. Unix peer authentication, SIGCHLD/Darwin reaping, complete session lifecycle, and full-duplex attach compatibility also lack live results. See source call sites in parent source audit: `jackin-capsule/src/main.rs`, `daemon/boot.rs`, `process_isolation/linux.rs`, `daemon/attach_accept.rs`, `runtime-attach-transport/src/transport.rs`.

Candidate B keeps gateway authority outside workloads and can group distinct sandbox identities under a logical instance. This POC only proves two OpenShell sandboxes and generic PTY connection/output replay. It does not prove Jackin-owned session arbitration, account admission/revision, account-scoped usage, approved credential operation, or owner-only inventory. Candidate selection is therefore **unresolved**; the full acceptance comparison is incomplete.

## Same-process reconnect correction

The first PTY transcript did not prove process continuity: it showed previous terminal output after reconnect, without a fresh command or process identity check. A bounded replay used a fresh OpenShell v0.1.5 gateway (jrr24-capsule-reconnect-poc, https://127.0.0.1:18823, mTLS with server verification), namespace jrr24-capsule-reconnect-poc, CLI 0.1.5, and Alpine ARM64 image digest sha256:2e0b81d60597f449baa56dc25d355367869d2dca4cd57e866f1e2b52af3eb55f. It created detached /bin/sh -i and recorded sandbox UUID, runtime generation, main-process instance ID, supervisor image ID, and sandbox image ID. The PTY client echoed the submitted echo FIRST-PID=... command, but no shell output arrived before timeout. Therefore this replay does not establish that input reached the canonical process; it captured no PID and performed no post-disconnect identity read. The same-process reconnect outcome remains **NOT TESTED**. A process-group signal/exit result was not attempted.

Raw attempts are under reconnect-<run-id>/. The final attempt is reconnect-9715b34e5611/; its connect-before.transcript contains only the shell startup notice, prompt, and locally echoed input. Its ownership receipt records sandbox UUID e3b4deb2-0074-4092-8cf0-db8cc48e5f84 and runtime generation 40ffd9f5-17bc-4577-9c93-844ac8f66288. Cleanup issued delete only after a matching UUID observation, then saw zero matching API resources and zero namespace containers on the first poll. Other attempts also confirm scoped cleanup; do not treat failed interaction attempts as process-lifetime evidence. The gateway was stopped and its dedicated certificates and state were removed. Container image IDs are in each attempt's runtime-containers.stdout.

The run did not save a global Docker inventory immediately before its first create; a causal before/after claim about concurrent foreign resources is **NOT TESTED**. No operation targeted a foreign namespace or resource. Do not infer that unrelated inventory stayed unchanged from these runs.

## Cleanup and limitations

The two test sandboxes and failed provisioning attempts were removed or created no resource. OpenShell returned an empty inventory; namespace-filtered Docker inventory returned no containers. The Alpine image remains in the shared local cache because its shared cache ownership was not established. The Architect image belonged to a separate POC and was not removed. Both isolated gateway processes were stopped and their generated certs/state were removed. No unrelated mutation command was issued. The global Docker inventory changed during concurrent POCs: two prior IDs disappeared and five appeared. New containers carried `jrr24-worker-poc` or `jfr-20261024-a` namespaces; ownership and cause of disappeared IDs were not established. See `a-docker-before.txt`, `a-docker-after.txt`, and `a-unrelated-inventory-diff.txt`.

Result: Candidate A's existing root-started isolation path **FAILS** OpenShell's live non-root policy; exact Capsule runtime/transport **NOT TESTED**. Candidate B passes bounded sandbox/private-filesystem and earlier PTY-output primitives; same-process reconnect, host-owned session/account authority, and trusted operator separation **NOT TESTED**. Architecture decision remains **BLOCKED** because Candidate B's key authority and session mechanisms remain unproved. This is not full-refactor readiness evidence.
