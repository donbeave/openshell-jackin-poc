## Agent support is four separate claims

`jackin-core/src/agent.rs` enumerates twelve adapters: Claude, Codex, Amp, Kimi, OpenCode, Grok, Antigravity, Gemini, Cursor, Muse, OMP, Hermes. This does not prove any of them works under OpenShell. Architect admits six: Claude, Codex, Amp, OpenCode, Kimi, Grok. Every selected adapter needs separate evidence for:

1. Installation: adapter `install_block`, fallback installation and derived image recipe, plus observed installed version/digest. An adapter enum is not an installation result.
2. Role admission: `launch.rs` checks the role's declared agent list before launch.
3. Launch command: runtime adapter arguments, hooks, workdir, environment, shell/tool paths and generated agent configuration must be exercised.
4. Authentication: agent-specific sync/API-key/OAuth/ignore modes where implemented, refresh and private files must work. GitHub CLI auth is independent of model-provider authentication. Custom provider URLs, model and effort are retained through the agent-specific configuration path, not flattened into one OpenShell provider.

Claude supports sync/API key/OAuth token/ignore in the current source. Other adapters have different sync/API-key support and provider configuration; OMP/Hermes do not gain a generic environment API key merely from an adapter choice. Representative launch support may limit experiments to Architect Claude plus a second declared adapter, but the future supported-agent release matrix must explicitly qualify all advertised combinations.

## Authority, revocation and foundations

- Account admission and fingerprint/revision checks are active in launch and hardline. Current revocation denies later admission/reconnect; it does not promise immediate termination of already admitted sessions. A stronger runtime revocation guarantee would require a separately specified policy and proof.
- Credential/configuration publication uses staging, swap and recovery. Interruptions must not assign an account partially. Private account homes, caches, history, plugins and auth configuration must not become project-shared data.
- Usage relay actively maps peer UID/GID/PID start identity to scoped account capabilities (`usage_relay_proxy/authorization.rs`, `identity.rs`). A same-UID workload helper cannot replace this trusted authority in the new model.
- `capture_checkpoint()` in `jackin-isolation/src/capture.rs` has no production caller found. `credential_update_v2` is protocol foundation. Workflow grant inspect/readback has no production caller found. These are classified separately; tests/types do not make them working launch features.
- `jackin-isolation/src/finalize.rs:242,275` actively probes Capsule session count during foreground finalization. Exec failure or unparseable output is treated as sessions present, preserving work. This is distinct from uncalled checkpoint capture. Preserve this fail-closed behavior over the new transport.
- Preservation guards are active when a hold exists. Normal hold creation is not demonstrated; host daemon checkpoint records `preservation_hold: None`. Workflow history checkpointing is not isolation capture.
- Sudo provisioning is active conditional setup. It is not evidence that interactive agent sudo is needed. OpenShell rejection of root still affects trusted Capsule UID switching and managed Docker setup.
- Apple launch/eject/reconnect dispatch is real, but finalization explicitly returns `apple-container finalize not yet implemented - Phase 0`. The new VM target requirements are not a claim that old Apple finalization worked.

## Public changes proposed after fresh setup

Keep normal role/account/workspace/session and lifecycle command meanings. Add `target add/list/select/remove` and `--target <id>` for load/management/prewarm; `status --all-targets --json` returns target availability separately from instance rows. Exact spellings are proposed API changes, not existing commands. Replace the existing `[runtime].default_backend` and workspace runtime `backend` configuration selectors with explicit target references in fresh configuration. No current public `--backend` flag was found in the CLI audit; do not document its removal as an existing command change. Retired configuration values receive a fresh-setup diagnostic rather than legacy-state import. Keep explicit Docker capability grant in role/workspace resolution, disabled by default. Doctor reports builder/gateway/capability health separately. No legacy state import, format preservation, or automatic deletion of old resources is part of this research.

New distributed behavior: remote project replica publication/export/conflict resolution, target authentication and unified fleet inventory. Windows and general collaboration remain future design requirements. None is represented as existing desktop behavior.
