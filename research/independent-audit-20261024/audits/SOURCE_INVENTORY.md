## Classification and exclusions

- Active in pinned source: Docker launch, image build, profile argument assembly, workspace materialization, cleanup decisions and listed calls. Jackin itself was not executed against the requested commit in these audits. Unit/mock tests are source evidence only, never runtime passes.
- Active but not demonstrated against OpenShell: all role lifecycle, Capsule/session/usage, Docker capability management, verification worker, fleet status, recovery/prune, and workspace live binds.
- Implemented without a production caller (confirmed by repository-wide symbol-reference search): `capture_checkpoint` and its capture API/tests; `compare_grant_vs_actual` and grant readback; `DockerApi::inspect_full_container_by_id` and its concrete adapter implementation; `DockerApi::pause_container_by_id` / `unpause_container_by_id` outside the inactive checkpoint foundation; `exit_diagnosis::diagnose_premature_exit` and `inspect_attach_outcome` production exports (test-only re-exports); `discovery::list_running_agent_display_names`; protocol `credential_update_v2`. Do not promote these foundations to current workflows. Separately, `docker::start`, Docker preflight, stale-image sentinel, sibling prewarm, background sidecar prewarm, and `absent_container_can_apply_model_and_effort` do have production callers; see ledger and independent corrections.
- Incomplete: Apple Container dispatch is real but `finalize` has an explicit Phase 0 failure; see separate Apple audit.
- Planned only: remote/Kubernetes target registry and fleet workflow; no source compatibility claim.

Excluded source matches: tests and `crates/testing` Docker fakes/expected CLI command strings are test infrastructure; `crates/tools/jackin-xtask/src/construct/tests.rs` launches Docker only to build/test release fixtures; Dockerfiles and construct scripts provide image builder/role tooling; docs and error text describe behavior but don't execute it. `crates/services/jackin-runtime-apple-container-*` calls `container` as a distinct Apple backend, not Docker; it is separately inventoried and incomplete. Do not delete useful process-runner, output-capture, redaction, image recipe, or generic cleanup code solely because its crate name contains Docker.

## Coverage and review limit

The source review covered 207 direct operation/API rows, 10 cross-cutting process/identity rows, 19 executable build/test infrastructure rows, 3 source-assumption reconciliation records, and one separate active-but-incomplete Apple finalization behavior record. All direct rows have independently reviewed action classification and a verified static caller route or explicit no-production-caller disposition. The 10 cross-cutting and 19 infrastructure rows also received independent static action/caller review. Broad scanning has 1,266 line-level dispositions and zero unresolved tokens; documentation, tests, configuration, imports, signatures, diagnostic text, telemetry, and build/test commands each carry an exact-line reason.

The required source behavior enum is recorded separately on each production row: the direct ledger has 192 `Active but untested` rows and 15 implemented foundations without a production caller. Apple’s active hardline finalization failure is recorded separately as `Incomplete`; Apple run/start/stop/remove/inspect/list operations are not mislabeled incomplete because of that separate failure. The cross-cutting, infrastructure, and assumption rows are `Active but untested`. None are classified `Active and demonstrated` because tests/mocks and source code do not demonstrate unchanged Jackin execution. All `replacement_execution_proved` values are false. This audit closes the source inventory gate only; it does not close OpenShell capability, target, storage, identity, credential, session, or optional Docker execution gates. See `source-inventory.json`, `broad-source-matches.json`, and `INDEPENDENT_AUDITS.md` for row-level provenance.
