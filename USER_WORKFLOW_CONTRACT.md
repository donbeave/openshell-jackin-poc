# User workflow contract for the full OpenShell refactor

This contract uses Jackin `6e266406b49da2ab3c55355f3b7d33d1643ee6cd`. See [source inventory](SOURCE_INVENTORY.md) for exact file/symbol/caller records and [compatibility analysis](results/full-refactor-20261024/compatibility.md) before reusing earlier evidence. “Implemented” below means an active source path; it does not claim this research executed the unchanged product successfully.

Fresh setup is allowed. Legacy container/state/configuration import is not required. Data created by the new design must retain the normal persistence and recovery contract. Reset permission does not authorize unrelated cleanup.

## Incomplete and inactive foundations

Apple Container is selectable but its finalize path explicitly fails with Phase 0; this is not demonstrated parity. Its unused remove wrappers are not an active removal guarantee. Runtime checkpoint byte capture, grant readback/compare and ordinary preservation-hold production have no production caller where documented in the audits. Workflow checkpoint metadata recording is active and different. A future design that needs live consistent capture must add and test a write barrier; source stop/start does not provide one.

## Public interface decisions to implement later

Keep existing command workflows. The proposed changes are explicit design decisions, not implemented CLI behavior:

- Add `jackin target add/list/show/remove` and `--target <alias>` where a target must be chosen. Workspace configuration chooses a default; existing logical instances keep their stored TargetRef. A conflicting target override for hardline/eject/purge is an error, not implicit retargeting.
- Replace fresh configuration fields `runtime.backend` and `runtime.default_backend` (`docker`, `apple-container`) with target/profile references. No per-call Apple backend flag was found that needs emulation. No legacy configuration import is planned.
- Human status/console show all registered authorized targets. Add `--all-targets` for explicit fleet machine output and `--target` for narrowing batch management. Preserve exile's “all managed roles” intent across registered authorized targets; its expanded target universe is documented rather than silently narrowing to one gateway. Prune uses authorized target-aware references conservatively and never drops retained data because a target is unavailable. Unavailable targets remain visible and are not purged.
- Preserve existing JSONv1 for the default/explicit single-target compatibility view. Add `--schema-version 2` for target/domain-aware output; require it for `--all-targets --format json` rather than silently dropping identity or overloading names. Current JSON availability and useful local fields remain. New schema and error contracts require release tests.
- Retain `load --rebuild` (already implemented). Add the same explicit `--rebuild` to image prewarm; the current `prewarm` has no force flag. Cache identity must be fixed before reuse; manual removal of tags is not the final user workflow.
- Keep explicit engine prewarm behavior. Existing `prewarm --daemon`, `--sidecar`, `--sidecar-container` and `--keep-sidecar-container` become documented aliases of managed-engine image/preparation/adoption operations where supported; they never invoke the old runtime manager. Ordinary prewarm does not grant Docker to a sandbox.
- Add verification-target selection to workflow test recording/configuration, independently of implementer agent target or Docker grant. The approved verification policy includes the target security profile; runtime unavailability does not trigger fallback.
- Preserve builder endpoint selection separately from target selection. Management against a live target does not require a healthy builder; new image construction does.

These public changes and JSON compatibility decisions belong in the refactor release notes and acceptance tests. They do not constitute a passed product test suite.
