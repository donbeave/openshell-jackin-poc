# Responsibility and resource ownership map

OpenShell is the only proposed executor for agent sandboxes and verification workers. Docker remains a separate image builder. No old Docker or Apple agent-execution backend is retained as a fallback. The candidate has unresolved required interfaces; this document is a design, not a claim that an unwritten refactor works.

| Component / decision | Owner | Authority and retained records | Removal / recovery boundary |
|---|---|---|---|
| Logical instance, role trust and workspace/account selection | Jackin trusted host logic | Instance ID, role revision, authorized workspace, account revision and chosen target/profile | Product decisions remain outside workloads; fresh setup uses a new state model, without legacy import. |
| Docker/Buildx image construction | Jackin image-builder service/CLI adapter | Explicit builder endpoint; recipe/input digests; selected agent/tool/platform; built config and OCI descriptors | Prune only owned unused builder artifacts after checking active and retained references; do not use role-container discovery as the reference authority. |
| Gateway bootstrap and trust | Target operator; Jackin stores its registration | Gateway/driver/endpoint/workspace/platform tuple, trusted CA/server identity and operator credential reference | Separate state, credentials and namespace per gateway; target unavailable never means its instances are gone. |
| Agent/workflow sandbox lifecycle | OpenShell gateway and compute driver | Immutable sandbox ID, canonical name, runtime generation, actual image and enforcement observations | Stop/restart is a process boundary. Delete must bind to the expected identity and confirm completion; name-only mutation is insufficient. |
| Session/account domains | Trusted Jackin host control | Domain ID, account revision, private-state references and allowed session operations | Each agent/session sandbox has only its domain data and project grants. Shell is a separate domain. Host control, not an agent-UID helper, owns authorization. |
| Canonical process and terminal | OpenShell; Jackin retains logical session/UI semantics | Session↔sandbox/generation/main-process identity, operator lease, exit/events/observation state | Released canonical PTY reconnect primitive is proved. Full control leases, protocol/host actions, account operations and real-agent journey remain unproved. |
| Local host project attachment | Trusted Jackin/target storage preparation; OpenShell admission | Canonical authorized source plus approved named-volume identity/options/labels and target path | The demonstrated Docker local bind-backed volume is an external prepared resource. OpenShell does not authorize its underlying path for Jackin. Retire only after consumer and ownership checks. |
| Remote/Kubernetes/VM storage | Target-specific storage owner | Explicit source authority, persistent-state locator, access mode, synchronization/export policy | No inferred live local sharing from copies. VM admission/confinement and required remote/cluster storage are unresolved. |
| Private account/home/config/history/plugin data | Jackin account authority; target persistent storage | Domain-scoped private mount references and publication revision | No shared private mount with generic shell or another account. Interrupted publication must not leave a partially assigned account. |
| Credential approval and usage | Existing trusted Jackin authorization/provider logic | Origin-bound domain/session, requested binding, operator decision and consumer receipt | Secret consumer and transport must be separately proved. Agent I/O cannot approve requests, refresh another account or trigger desktop authority. No new production broker is built here. |
| Optional managed Docker engine | Required OpenShell-compatible managed-compute/companion owner, not implemented | Per-granted-domain engine ID, CA/client boundary, data/network/port/child ownership and teardown receipts | External fixture proves forwarding only. A managed lifecycle with interruption/recovery is missing; the old Jackin DinD manager is not silently retained. |
| External engine test fixtures | Experiment scripts only | Exact container/data/certificate/network/port receipts | Fixture cleanup is not OpenShell-owned cleanup. Children do not inherit agent policy. |
| Verification policy and result | Jackin workflow host service | Candidate commit/tree, approved argv/policy hash, trusted bundle/image, one-use worker ID and observed result | OpenShell executes; Jackin validates/binds results. Missing runtime, timeout or uncertain cleanup never becomes a test pass. |
| Host desktop actions, keep-awake and terminal restoration | Initiating Jackin desktop client | Authenticated target/session origin plus explicit user/action authority | Desktop effects return to the correct client; raw terminal bytes are never trusted control frames. |
| Ownership receipts and recovery intent | Jackin retained lifecycle logic | Resource kind, authority, target/scope, immutable identity, retained-data reference, operation request ID and phase | Record before external effects. No prefix-only cleanup. Uncertain absence or unauthorized/unavailable scope preserves retained work. |

## Retained direct Docker operations

Only these responsibility classes are allowed in the future refactor. The call-level source inventory assigns each current operation to a class or removal/replacement decision.

1. **Builder:** select/validate the explicit Docker endpoint; Docker/Buildx build, inspect image/recipe metadata, pull required builder bases, and remove unused owned builder images after target-aware reference checks. Agent-version execution uses build metadata or OpenShell, never a direct `docker run` probe.
2. **Explicit workload capability:** Docker CLI, Buildx, Compose and Testcontainers inside a granted sandbox talk only to its declared engine. The normal sandbox has no usable engine credentials/socket. Builder authority is not inherited.
3. **OpenShell infrastructure:** an explicitly identified driver/target operator may prepare approved storage or engine infrastructure. It does not execute agents or verification checks through a second backend. A fixture is not proof of a production-managed lifecycle.

Remove Docker/Apple run/exec/attach/status/snapshot/usage/finalize/verification-worker paths as agent-runtime mechanisms. Preserve generic process, parsing, hashing, Git, role/account and desktop utilities. Image/engine infrastructure code must have its own narrow owner/interface instead of keeping the old general runtime manager under a new name.
