# Runtime capability matrix

This is execution evidence for small proofs of concept, not a Jackin implementation or a production-readiness claim. Source inspection is identified separately in [sources](results/sources/README.md). A reproduced restriction is a failure for the affected capability.

## Scope and versions

P1 is macOS ARM64 with the OrbStack Linux ARM64 Docker engine. It is **not Docker Desktop** and is not a native Linux-host result. OpenShell CLI and gateway are published stable **v0.1.5**, commit **bdb956f2cd65a635f1294fccf1d138d263bf650f**, selected at the start. No other OpenShell release or source patch is included. The local builder endpoint is `unix:///Users/example/.orbstack/run/docker.sock`; client 29.9.2, engine 29.8.2. The separate gateway is `ojp-20261024-gw`, mTLS `https://127.0.0.1:18770`, Docker driver, launch JWT signing, resource admission enabled, and unique `sandbox_label = "ojp-20261024"`. See [environment](results/environment.json), [gateway configuration](experiments/gateway/gateway.toml), and [resource identities](results/resource-identities.json).

The final Rust-ready image is `ojp-20261024-agent:2.1.310-poc-v3`, ID `sha256:88b9118075feb284f28b34bb8baa4568aff8ab75c22022441e52a37079049ba4`. It contains Claude Code 2.1.310, Rust 1.99.1, mise 2026.10.18, mbx 1.27.0, nextest 0.9.149, Docker CLI 29.9.2, buildx 0.38.1, and Compose 5.6.1. Earlier image failures remain in `results/image/` and `results/native/`; their recipes are preserved as `Dockerfile.initial` and `Dockerfile.v2`. Agent version 2.1.309 was also verified inside an OpenShell sandbox. Image-only `ENTRYPOINT` execution is not assumed.

Result is one of PASS, FAIL, BLOCKED, NOT TESTED. Mechanism is one of RELEASED, CONFIGURATION, EXTERNAL FIXTURE, WORKAROUND, EXPERIMENTAL PATCH. Each row uses one primary mechanism; supporting configuration is described in the observation. A NOT TESTED mechanism names the intended method, not a compatibility claim.

## Requirements derived chiefly from Architect

| Category | Required behavior | Source and boundary |
| --- | --- | --- |
| Image builds and installed tools | Build selected agent and development tools before launch; change actual agent version | Architect tool/environment contract; only a small tool subset is built |
| Process control and terminal access | Exec with output/status, interactive input/resize/signals, detach/reconnect | Architect autonomous shell workflow and Jackin interactive load |
| Project files and retained data | Project files, shared source mounts, retained state and exported results | Architect `/workspace` contract and Jackin per-agent state |
| Environment variables, hooks, credentials | Role startup hook, non-secret env, separately scoped credentials | Architect preflight/plugins; real account/provider product logic is outside scope |
| Network policy and resource limits | Scoped endpoints, development binaries, enforceable resource limits | OpenShell runtime requirements; Architect does not supply numeric limits |
| Sandbox lifecycle | Create, inspect/list, stop/start, delete, simultaneous isolated instances | Jackin isolated parallel agents and retained state |
| Optional Docker access | Ordinary instance has none; selected instance can use dedicated engine, Compose and Testcontainers | Jackin's stated Docker-in-Docker behavior; native ownership is a separate requirement |

Architect commit: `7b72b38fe1d66e35c0931899c53bf3719592bbcc`; Jackin commit: `7d4b8acea25d28fd5286c958e3890148fc2bf40e`. Jackin controllers, schedulers, dashboards, worker protocols, account selection, plugins, and product logic are outside this experiment.

## Collateral environment finding

Three original Docker sandboxes were later found stopped; their common exit timestamp predates cleanup. They were running in the initial inventory. The early default-namespace overlap is a plausible cause, but the initial actor is not established by retained logs. The isolated gateway configuration fixed the separately reproduced namespace collision. The incident, safe owner-API diagnostic and approved restoration are recorded in [collateral analysis](results/collateral/gateway-analysis.md). Do not interpret experiment-resource cleanup as evidence that all original workloads remained running.

The supplementary Python 3.13 TLS-negative probe in `results/main/missing-client-tls.json` failed local strict certificate validation (`Missing Authority Key Identifier`) for the generated fixture CA. It was not counted as a peer credential rejection. The Docker missing-client and B-trust/A-client probes establish the stated TLS negative results without relaxing certificate checks.

### Approved restoration completed

The user explicitly approved corrective work. The original gateway API stopped and restarted the three exact original sandbox IDs using its existing valid mTLS identity, with TLS verification enabled and no global CLI configuration changes. [Restoration actions](results/collateral/restore-originals-execution.json) returned PASS; [subsequent verification](results/collateral/restoration-verification.json) shows all three Ready and successful harmless exec. This corrects current state without resolving the unproven initial termination actor. Experiment resource cleanup remains separate.
