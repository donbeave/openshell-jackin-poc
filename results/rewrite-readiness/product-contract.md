# Jackin product contract for an OpenShell rewrite

**Source baseline:** `jackin-project/jackin` commit [`41bad147b5ba9db09be99b07248531ce1bd867be`](https://github.com/jackin-project/jackin/tree/41bad147b5ba9db09be99b07248531ce1bd867be), current main requested for this review. Earlier PoC baseline `7d4b8ac` is stale for product scope. This document distinguishes the checked-in implementation and tests from plans and marketing claims. Jackin itself warns it is early-development software and not production-ready; the feature set is not a compatibility promise ([README.md](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/README.md#L1-L10)).

## Product in one sentence

Jackin is the operator layer around coding agents: it selects a reusable role/tool profile and a workspace/file-access boundary, builds and launches an agent runtime in an isolated environment, injects authorized credentials, preserves per-instance agent state, and lets the operator supervise parallel instances. It does not implement the agent itself. The README and runtime-model page are incomplete at this commit; the core `Agent` enum defines twelve runtime adapters ([README.md#L12-L61](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/README.md#L12-L61), [agent.rs#L14-L58](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/core/jackin-core/src/agent.rs#L14-L58)). Each role may restrict its supported subset.

## What users can do today

### Choose role, project access, and launch

- `jackin` (interactive terminal only) opens the operator console; `jackin console` is explicit. The console is the normal daily surface; `jackin load` is the direct/scriptable-style launch command but still requires a rich terminal and runs a full-screen progress UI ([console.mdx#L6-L24](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/console.mdx#L6-L24), [load.mdx#L6-L27](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/load.mdx#L6-L27)).
- A **role** is an external/reusable tool profile: its repository owns the Dockerfile, manifest, tools, runtime support, and plugins. A **workspace** defines the mounted host paths, working directory, allowed roles, and account authorization. This role/workspace split is product logic, not a container primitive ([runtime-instance-model.mdx#L14-L21](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/reference/runtime/runtime-instance-model.mdx#L14-L21), [workspace.mdx#L12-L30](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/workspace.mdx#L12-L30)).
- Launch resolves a role selector and workspace/path, validates access and role trust, gathers role manifest values and account choice, then performs identity/credentials/image/workspace/network/sidecar/capsule setup with progress and actionable prompts ([load.mdx#L13-L25](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/load.mdx#L13-L25)).
- Workspace configuration includes bind mounts (including read-only mounts), a container workdir, default/allowed roles and agents, git-on-entry behavior, and workspace settings. Workspaces may target saved projects or ad-hoc paths. The workspace docs are the user-facing contract; CLI and workspace command implementation live in `crates/apps/jackin/src/{cli,app}/workspace*` ([workspace.mdx](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/workspace.mdx), [jackin crate map#L5-L29](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/apps/jackin/README.md#L5-L29)).

### Accounts and auth

- First start scans supported agent credential locations and non-empty provider API-key environment variables. `account scan` repeats discovery; values are not printed. Empty directories/config without credential evidence do not count as accounts ([account.mdx#L6-L27](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/account.mdx#L6-L27); discovery implementation and tests: [discovery.rs](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/core/jackin-config/src/accounts/discovery.rs)).
- Users can register profile directories, provider API keys, or Claude OAuth token references, then separately authorize accounts for a workspace and select a default per agent. Authorization is intentionally workspace-scoped. Credential resolution, secret references, import/copy behavior, and masking are Jackin domain behavior; a sandbox's generic secret injection does not replace them ([account.mdx](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/%28public%29/commands/account.mdx), [accounts discovery](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/core/jackin-config/src/accounts/discovery.rs)).
- The source `Agent` enum/runtime adapter dispatch supports `claude`, `codex`, `amp`, `kimi`, `opencode`, `grok`, `antigravity`, `gemini`, `cursor`, `muse`, `omp`, and `hermes` ([agent.rs#L14-L58](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/core/jackin-core/src/agent.rs#L14-L58)). Each role’s manifest declares a subset, validated before launch (`runtime.rs#L83-L103`). The `runtime-instance-model.mdx#L14-L21` five-agent list is stale/incomplete at this pin; code takes precedence.

### Sessions, files, Git, and parallel work

- `load` creates a **fresh instance**; `hardline` reconnects/restarts/rebuilds/inspects an existing instance and can start an additional session. `eject`, `exile`, purge and console actions cover lifecycle/recovery. A fresh load takes a new DNS-safe instance name even if old instances exist; missing recoverable state may prompt/block rather than silently supersede work ([runtime-instance-model.mdx#L23-L30](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/reference/runtime/runtime-instance-model.mdx#L23-L30)).
- A Docker instance has a role container, network, Jackin metadata and durable per-instance agent home; DinD and its cert volume are conditional on effective grants. Conversation history, runtime-local config, auth handoff and agent state are intended to survive container recreation. Container writable-layer mutations are explicitly not recoverable; recovery is from host-backed workspace/worktree/clone/home/metadata state ([runtime-instance-model.mdx#L16-L21](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/reference/runtime/runtime-instance-model.mdx#L16-L21), [README.md#L39-L48](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/README.md#L39-L48)).
- Parallel agents can use the same or different projects; workspace mounts determine file visibility and role determines tools. Shared/Worktree/Clone modes and fresh-only configured Git pulls are traced into current implementation in the source map below; those are static findings, not runtime validation. The rewrite must preserve every implemented Git/worktree policy and recovery invariant, not merely mount a directory.
- The capsule provides interactive terminal multiplexing/control, multiple tabs/sessions, status, attach/reconnect, shell access, clipboard/file export and agent event/status integration. These are shipped surfaces in `jackin-capsule`; they are first-party UX/protocol logic and are not supplied by an execution sandbox. Entry point routes PID1 to daemon and normal invocations to client ([capsule main.rs](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/apps/jackin-capsule/src/main.rs), [capsule crate map](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/apps/jackin-capsule/README.md)).

### Role hooks and extensions

Role hooks such as `setup-once.sh`, `source.sh`, and `preflight.sh` execute as authored in the standard start flow; a non-zero result fails startup and is surfaced. Jackin deliberately does not inspect, rewrite, rate-limit, or sandbox the hook body. Preserve ordering, environment, instance-state effects, and failure propagation when changing runtimes ([ADR-009#L6-L23](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/docs/content/reference/adrs/adr-009-role-hooks-authors-domain.mdx#L6-L23)).

## Replaceable runtime vs Jackin-owned behavior

| Concern | Replaceable runtime mechanism | Jackin product contract that remains required |
|---|---|---|
| Isolation/process lifecycle | Docker container/daemon, networking, resource limits, image execution; potentially OpenShell sandbox | Fresh instance identity; create/restore/reconnect/teardown decisions; visible state/errors; parallel session UX |
| File access | Runtime mount/volume API | Workspace CRUD, mount policy, allowed-role/account policy, workdir resolution, Git/worktree semantics, recovery data model |
| Images | Runtime build/pull/cache | Role trust and manifest handling; role image construction/selection/version decisions; lifecycle hooks and launch progress |
| Credentials | Runtime secret/env transport | Discovery/import, account naming, source references, workspace authorization/default selection, provider/runtime-specific staging and persistence |
| Interactive execution | Sandbox exec/PTY/attach | Capsule daemon/client protocol, tabs, terminal UX, status/events, shell and recovery actions |
| Network | Runtime policy/egress controls | Jackin network intent and per-role/workspace configuration/UX; policy-to-runtime translation and user-visible failures |

The Docker adapter is currently an adapter behind `jackin-runtime`, but that does not mean Jackin product semantics are Docker semantics. The crate describes the CLI as the operator-facing glue, while runtime/launch contains Docker-specific execution code ([jackin README#L3-L14](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/apps/jackin/README.md#L3-L14), [docker launch adapter](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/services/jackin-runtime/src/runtime/launch/launch_runtime/docker.rs)).

## Shipped, foundation, and planned distinctions

- **Shipped in source:** console and CLI, workspace/account management, current named agent runtimes, role image/manifest flows, Docker-backed instances and DinD, capsule terminal/control, durable host-backed state, role hooks, and test suites across CLI/runtime/capsule. The workspace itself labels Jackin early development, so “shipped” means implemented in this commit, not production support.
- **Foundation, not a user promise:** OpenShell PoC-tested runtime primitives and the existing adapter boundaries are evidence for feasibility only. They do not provide role/workspace/account policy, capsule UX, Jackin state recovery, or product orchestration. The PoC records these as outside its scope.
- **Planned/design-only:** anything documented under `docs/content/roadmap`, `docs/content/research`, or architecture proposals unless current code + tests prove implementation. In particular, roadmap agent orchestration, remote/fleet scheduling, and future runtime/platform backends must not be described as current parity merely because design docs exist.

## Minimum parity acceptance for a rewrite

1. Preserve the console plus direct `load` flow, clear selector/workspace distinction, launch progress, validation/prompts, and error behavior.
2. Preserve role image/manifest contract and role hook sequence/failure semantics.
3. Preserve workspace access boundary, mounts/workdir, allowed roles/agents, per-workspace account grants/defaults, and Git/worktree/restore behavior.
4. Preserve currently supported runtime/auth combinations and safe account discovery/import/staging; preserve the twelve source-enumerated runtimes and per-role support filtering, rather than relying on the stale five-name runtime-model page.
5. Preserve independent named instances, parallel agents, fresh-load vs reconnect/new-session ownership, instance identity, durable agent home, recoverable-state warnings, and metadata/rebuild behavior.
6. Preserve interactive capsule behavior: attach/reconnect, terminal dimensions/input/signals, session/tab controls, status/events, shell and file/clipboard affordances implemented in the pinned source.
7. Keep runtime security controls and Jackin policy aligned: isolation, mounts, network, credentials, resource constraints and exposed boundary need explicit translation; a runtime passing primitive PoCs alone is not product parity.
8. Verify claims against source and tests at this pinned revision. README and docs describe intent; implementation and focused tests decide what is live. Avoid counting roadmap-only features.

### Docker and DinD lifecycle

Docker is the complete/default active backend. A fresh Docker launch creates a per-instance role network and conditionally creates a privileged Docker-in-Docker sidecar only when effective role grants enable DinD (or adopts a prewarmed sidecar); persisted resources include role container, network, and conditional DinD/cert volume ([runtime dispatcher#L153-L168](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/services/jackin-runtime/src/runtime/launch/launch_pipeline/launch_core/orchestrate/runtime.rs#L153-L168)). The DinD manager creates the network, ensures/pulls its image, mounts its own TLS cert volume, applies labels tying it to the owning role, starts it, and waits for readiness ([launch_dind.rs#L88-L140](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/services/jackin-runtime-launch-dind/src/launch_dind.rs#L88-L140), [#L143-L240](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/services/jackin-runtime-launch-dind/src/launch_dind.rs#L143-L240)). The cleanup adapter resolves handles and removes role plus associated runtime resources under ownership checks; tests in `crates/services/jackin-runtime/src/runtime/cleanup/tests/case_01.rs` and `case_05.rs` exercise cleanup/resource isolation. DinD is a role grant, not an unconditional container feature.

### Mount isolation, Git, and persistence

Current mount-isolation types distinguish `Shared`, `Worktree`, and `Clone` ([jackin-core isolation.rs#L20-L42](https://github.com/jackin-project/jackin/blob/41bad147b5ba9db09be99b07248531ce1bd867be/crates/core/jackin-core/src/isolation.rs#L20-L42)). `jackin-isolation/src/materialize.rs` allocates worktrees and clones under per-instance state (`worktree_path_for` lines 44–52; `clone_path_for` lines 54–62), prepares Git backlink/override mounts to make host-backed worktrees usable in the container (lines 96–134), and branches by isolation mode at lines 400–440. `Shared` exposes the same source; `Worktree` uses a separate linked worktree; `Clone` materializes a separate clone. ### Agent-account auth (distinct from usage host-authority foundations)

The shipped product account model is in `crates/core/jackin-config/src/accounts.rs` and `.../accounts/discovery.rs`; discovery checks agent profile layouts and provider API-key environment variables. `AiProvider` enumerates upstream service providers, which is a separate axis from agent executables: API providers include Anthropic, OpenAI, Amp, xAI, OpenCode, Moonshot/Kimi, Z.ai, MiniMax, Google, Cursor, Meta, and OpenRouter (discovery mapping at `discovery.rs#L19-L100`). Accounts can be profile directories, API keys, Claude OAuth token references, or secret references; the workspace gate is resolved into instances, not supplied by OpenShell.

For launch, `jackin-runtime-launch-capsule-setup/src/capsule_setup.rs#L11-L67` resolves selected account IDs into auth mode, source path, provider/selector and XDG roots. It assigns each instance a separate auth/home/cache/forwarded directory (`#L201-L270`); current Kimi and Hermes forwarding uses a Jackin per-instance store directory, while other runtimes get selected credential files staged into that store (`forwarded_credential_mount_paths`, lines 201–228). Instance-specific auth-directory staging/swap is implemented in `jackin-instance-credentials/src/auth_directory/stage.rs#L19-L110` with atomic staging, previous-directory backup, journal phases, and host-missing behavior. Runtime-specific helpers are in `crates/services/jackin-instance-agents/src/{claude,codex,amp,kimi,opencode,hermes}.rs`; `hermes.rs` and `kimi.rs` are explicit stage/sync implementations. State/config update and reconnect admission are versioned/fingerprinted so an instance cannot continue with a changed account selection: `runtime/launch/launch_pipeline/launch_core/orchestrate/runtime.rs#L41-L43`, and `runtime/attach/hardline.rs#L75-L87` checks current account admission. Treat A1 host authority and B2.1 signed transcript as inactive foundations for this Jackin rewrite, not required shipped account behavior. ## Settled parity judgment

A rewrite must preserve the Docker path and its exact role/workspace/account semantics. It must also handle Apple Container as a real but incomplete backend if the rewrite is intended to replace all current backend paths; source dispatch exists, but lifecycle completeness is explicitly unfinished. No active VM backend was found at this commit. DinD's independent engine, TLS cert material, conditional privilege/grant policy, role-resource ownership, and cleanup are user-visible security/isolation contracts. Preserve the three Git mount modes (shared/worktree/clone), per-instance backing state and worktree Git links, plus fresh-only configured Git pulls. Preserve only the active coding-agent auth stack above; the usage host-account authority and V2 signed transcript mechanisms are not production dependencies in launch/reconnect. The PoC runtime-primitive result therefore remains narrower than product parity: most missing work is Jackin-owned policy, state, orchestration, account/auth and terminal control, while Docker container/network/volume/process calls are replaceable runtime mechanics.
