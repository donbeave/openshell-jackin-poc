# Jackin rewrite evidence audit

## Decision

The PoC answers a useful runtime question: can released OpenShell host a prebuilt coding-agent image, persist a project volume, expose a dedicated external Docker daemon, and run Docker/Compose/Testcontainers work? On the tested macOS ARM64 + OrbStack Linux ARM64 profile, mostly yes, with material failures and workarounds.

It does **not** establish that OpenShell covers Jackin's current user behavior. The PoC drives OpenShell CLI/SDK directly, with scripts and a test image. It does not run Jackin's console/load/hardline flow, select a Jackin account, stage real agent credentials, exercise Jackin's role/workspace policy, attach a Jackin capsule session, or carry out a user's edit/build/test cycle through Jackin. The missing product integration is the central evidence gap.

| Decision | Readiness | Reason |
| --- | --- | --- |
| Start rewrite design and a bounded prototype | **READY, with explicit unknowns** | Enough evidence to design around OpenShell sandbox lifecycle and selected Docker mechanics. Prototype must test Jackin orchestration/account/session/files and current client compatibility; Docker/TTY/API boundaries are not equivalent by assumption. |
| Commit to full replacement of Jackin's current runtime | **NOT READY** | No comparative end-to-end Jackin workflow, account/auth parity, state semantics, hook/policy parity, or host-workspace mount proof. Several scoped-egress runtime requirements fail or use unvalidated workarounds. |
| Ship user-visible parity | **NOT READY** | No Jackin user journey was exercised; no authenticated agent task; no host-repository Shared/Worktree/Clone mount proof or release evidence on the intended platform/backend matrix. |

“Start design/prototype” does not mean start a production integration or claim parity. It means the research now supports a scoped, reversible technical prototype whose acceptance criteria explicitly include the uncovered product behaviors.

## What PoC execution proves

Evidence scope is released OpenShell CLI/gateway v0.1.5 (`bdb956f2cd65a635f1294fccf1d138d263bf650f`) on macOS ARM64 with OrbStack Linux ARM64 Docker engine, not Docker Desktop. No Jackin code changed. The fixtures, credentials, and engines were test-only; engine provisioning/cleanup was external.

- **Images and launch:** image build before sandbox creation and actual Claude Code versions 2.1.310/2.1.309 were observed. Only a small tool slice was built. No authenticated agent task ran. See `results/image/`, `results/basic/create-jwt.json`, `results/basic/exec.json`, `results/repeat-final/image-versions.json`.
- **Sandbox lifecycle and terminal:** Python SDK lifecycle/list/get/exec/stop/start/wait-ready is demonstrated. Exec preserved exit code/stdout/stderr; CLI TTY input, resize, Ctrl-C, detach/reconnect were exercised. This does not establish Jackin capsule sessions. Source inspection of the saved OpenShell Rust client snapshot (`results/sources/openshell-rust-sdk-config.rs`, `openshell-rust-sdk-transport.rs`, `openshell-rust-sdk-client.rs`) finds no client-certificate field in SDK config, transport identity explicitly absent, and curated exec buffers output with TTY false. OpenShell CLI legacy/raw paths exist, so this is a client-integration gap to test, not proof that native Rust or interactive attach is globally impossible. No native Rust mTLS, Jackin capsule transport, or capsule daemon runtime test was performed. Jackin capsule transport expects Docker exec `-i` plus its direct Unix socket; compatibility with OpenShell's transport remains unproven.
- **Project files and retained state:** explicit upload, same-path live-bind exchange between agent and external-engine child, project persistence over stop/start, and per-instance fixture volumes are demonstrated. This was **not** a bind of Jackin's actual host repository into an OpenShell sandbox, nor proof of Jackin Shared/Worktree/Clone modes or recovery paths. Saved OpenShell runtime docs require `enable_bind_mounts=true` and `resource_admission.enabled=false` for documented host bind mounts; the PoC did not disable admission. Some repeat fixture entries show hook startup only succeeds with an explicit main command; the no-configured-hook probes fail. See `results/repeat-final/README.md`, `results/repeat-final/role-hook-explicit-main-shell.json`, `results/repeat-final/hook-check.json`, `results/sources/docs__how-it-works__sandboxes__runtimes.mdx`.
- **Docker and development loop:** selected sandbox connected with mTLS to a separate external daemon; Docker builds/runs, Compose, live source mount, and one native Rust Testcontainers data exchange passed. A forced harness termination left a child container/volume. Sandbox deletion did not remove external fixture children. Jackin's source already owns its DinD sidecar and explicit eject/exile teardown; the PoC does not show that Jackin needs OpenShell to own the engine. Docker-executed Rust workaround evidence is loopback-only with returned files; it does **not** prove changed Testcontainers rebuild + Docker mTLS/service-port access end to end. See `results/repeat-final/README.md`, `results/repeat-final/testcontainers-client-termination.json`, `results/repeat-final/testcontainers-after-termination-resources.json`, `results/repeat-final/engine-b-after-sandbox-delete.txt`, `results/native/docker-executed-rust-test.json`.
- **Network/identity behavior:** agent policy denied a direct request while the external daemon's child reached the same harmless endpoint; child traffic does not inherit agent policy in this setup. Same-path replacement of a native executable after rebuild was denied by integrity checking. A distinct target path and Docker-executed test worked as workarounds. An unrelated policy update closed active Docker/database streams; no-change control stayed open. These are real constraints for a transparent coding cycle, even if workaround acceptance is a product choice. See `results/repeat-final/native-same-path-v2.json`, `native-workaround-distinct-path-v2.json`, `testcontainers-client-termination.json`, `results/policy-streams/` and `results/network/`.
- **Isolation:** per-instance external engine and TLS keys, separate project volumes/ports, and independent Engine B repeat were demonstrated. This is an externally owned fixture model, not a reason to move daemon ownership out of Jackin. Current Jackin Docker profile defaults to network-open and DinD-none; conditional grants can enable DinD. Scoped-egress Rust/Testcontainers users still need same-path rebuild behavior proved. Ordinary sandbox lacked Docker socket/endpoint access. See `results/repeat-final/README.md`, `results/repeat-final/docker-socket-denied.json`, `results/ownership/`, `results/rewrite-readiness/gap-relevance.md`.

## Behavior not proved (and why it matters)

| Jackin behavior | PoC status | Consequence for rewrite decision |
| --- | --- | --- |
| Account discovery, named account selection, workspace authorization | **NOT TESTED** | Cannot claim account behavior parity. README establishes relevant UI/CLI expectations; PoC deliberately avoided personal credential files. |
| Agent API-key auth, OAuth login, refresh/expiry, provider profile choice | **NOT TESTED** | `results/agent-auth-availability.json` records no test credentials, no personal credential file reads, no auth attempt. A Docker daemon mTLS certificate is not agent authentication. |
| Interactive Jackin session lifecycle: attach, send, interrupt, reconnect, resume conversation | **PARTIAL at substrate only** | OpenShell CLI TTY proves byte input/resize/signal and reconnect. No Jackin capsule session was run. Saved Rust SDK source has no demonstrated client mTLS and its curated exec buffers with TTY false; raw RPC/CLI integration remains an untested route, not a proven impossibility. |
| Persistent agent state (history, GitHub auth, plugins) | **PARTIAL at storage only** | Project file retention over stop/start is not state migration, auth refresh, plugin persistence, or state continuity between Jackin sessions. |
| Workspaces, worktrees, file access and cleanup semantics | **NOT TESTED for host workspace parity** | Same-path exchange between agent and external engine is proven, but actual host-repository bind and Jackin Shared/Worktree/Clone behavior are not. OpenShell documented host binds require configuration that the PoC did not enable (runtime docs say `enable_bind_mounts=true` and admission disabled). |
| Role image build, environment, hooks and permissions | **PARTIAL** | Small Claude/Rust image and explicit hook command work. Full roles, provider injection, Jackin permission modes, and all supported agent entrypoints were not run. No real coding task/auth. |
| Alternate agents | **NOT TESTED** | Claude version only. No Codex/Amp/Kimi/OpenCode/Grok launch or account compatibility evidence. |
| Image build and local delivery across runtimes | **PARTIAL** | Local builder and same-daemon gateway worked; VM used explicit image import. No remote registry/distribution or full platform matrix. |
| Full user journey (`console`/`load` to edit/build/test and resume) | **NOT TESTED** | No Jackin command/UI invoked, no user-like workflow, no end-to-end acceptance record. |
| Runtime/engine ownership, isolation and cleanup | **PARTIAL** | OpenShell lifecycle and external fixture cleanup were tested. Jackin currently owns conditional DinD resources and teardown in source, so native OpenShell daemon ownership is not required. The rewrite must preserve Jackin's ownership semantics; no Jackin eject/exile/purge through OpenShell was tested. |
| Parallel projects/agents and platform coverage | **PARTIAL / NOT TESTED** | Fixtures establish narrow per-instance engine separation, not concurrent Jackin instances or same-project Shared/Worktree/Clone semantics. Docker Desktop, native Linux, remote gateway, Kubernetes not tested. Jackin Apple Container backend is present but `finalize` remains Phase 0/incomplete; no active VM backend appears in current dispatch. The narrow OpenShell VM PoC is not proof of Apple backend parity. |

The PoC matrix's P1 “full requested contract” is a valid **full-contract gate**, but too strict as a gate for beginning a design or limited prototype. Gap relevance differs: same-path native rebuild denial is a hard blocker for scoped-egress Rust/Testcontainers workflow, but not every current Jackin session because standard profile is network-open and DinD-none. Live policy-update connection survival is optional parity because no active Jackin path edits policy on a running instance. Immediate cleanup after test-process SIGKILL is not a current promise; explicit eject/exile removes the Jackin runtime stack and preserves persisted state. External daemon survival after OpenShell deletion is not a Jackin defect if Jackin retains engine ownership. Keep these findings visible, but do not promote them into product requirements absent a user-facing contract. See `results/rewrite-readiness/gap-relevance.md`.

## Evidence limitations and next proof

1. Trace current user journeys from commit `41bad147...`: console/load/hardline/eject/exile/purge, account staging, twelve role-filtered adapters, capsule, and Shared/Worktree/Clone state. Use static-source proof separately from executions; `product-contract.md` provides source/test map.
2. Prototype the actual Rust integration path. Test supported native authentication/transport (the PoC's Python SDK mTLS does not prove Rust SDK mTLS), curated vs raw exec/TTY, and Jackin capsule attach/reconnect. Test daemon-mode launch: Jackin supports a force-daemon env outside PID 1, but capsule attach depends on Docker exec `-i` and direct Unix socket; neither is covered by PoC runtime evidence.
3. Prove a real host-project boundary. Test Shared, Worktree, and Clone against the intended OpenShell bind/volume configuration, including admission/security implications, workdir, git links, recovery, and concurrent access. Existing agent-to-DinD volume bind is not host workspace proof.
4. Under scoped-egress profile, run Architect edit → same-path Cargo/nextest rebuild → Docker API and service-port Testcontainers test. Existing Docker-child workaround is loopback-only and not equivalent. Keep integrity checks enabled.
5. Preserve Jackin-owned resource semantics: conditional DinD grants, independent sidecar/TLS/network identities, hardline recovery, eject/exile teardown with state retained, purge only after runtime absent. Do not require OpenShell to become daemon owner. Prove cleanup through Jackin's own ownership path.
6. Run one approved authenticated agent task through Jackin, including account selection/staging/admission, tool execution, session output, persistence, and cleanup. Do not read personal credential files.
7. Expand platform proof only to intended targets. OpenShell's narrow VM slice is not Apple Container parity; current Apple backend is implemented but incomplete, and source dispatch has no active VM backend.

Until those runs complete, rewrite design/prototype can proceed as an evidence-gathering step. Full replacement commitment and user-parity claims cannot.
