# OpenShell PoC gaps versus Jackin users

## Scope and method

Read-only comparison. OpenShell execution evidence remains limited to stable v0.1.5 at `bdb956f2cd65a635f1294fccf1d138d263bf650f` on macOS ARM64 + OrbStack Linux ARM64 Docker. Jackin source is pinned to `41bad147b5ba9db09be99b07248531ce1bd867be`; its commit description identifies source tree `a9581e5b9435294fe5e64083760154bbba9ac63a`, which is what the saved source extracts identify. Architect source pin: `7b72b38fe1d66e35c0931899c53bf3719592bbcc`. This report uses local PoC scope notes plus read-only GitHub fetches of implementation/docs. It does not treat a behavior gap as a user promise unless Jackin evidence supports that promise.

Jackin describes itself as the ecosystem layer around agents, running parallel agents with scoped access, per-agent state, and visible host boundaries. The pinned runtime instance model lines 10–32 says a Docker instance comprises a role container, DinD sidecar, network, cert volume, and Jackin-managed state. Active `eject` docs say ejection removes role and DinD containers, certs and network while preserving persisted state; `--purge` additionally deletes that state. `exile` also preserves state. `hardline` reconnects/restarts a crashed runtime. Active cleanup code matches those semantics: eject removes the role and DinD container/resources, while purge first requires the backend absent and then removes the instance state directory. Jackin explicitly documents DinD children bypassing the role-container firewall and calls enforcement partial; active code installs `firewall-apply` in the role container only. Preserve these specific lifecycle transitions and disclose egress boundaries. Do not infer hot policy editing, immediate crash-child cleanup, inherited child policy, or OpenShell-owned daemon as established promises.

## Rewrite decision

The six gaps do not establish that Jackin users require OpenShell to be the daemon owner or that every OpenShell gap blocks a runtime replacement. Lifecycle boundary is the split between runtime teardown and persisted state: plain eject/exile tear down containers/resources and retain state; purge deletes state only after runtime resources are absent; hardline resumes/reconnects the retained instance. A rewritten runtime may use OpenShell as a lower-level sandbox and retain Jackin controllers for externally owned DinD/Docker resources and durable state. Preserve those explicit user actions; do not invent instantaneous crash cleanup or make sandbox deletion silently erase state.

Before claiming Jackin parity under scoped egress, prove the Architect workflow: edit a Rust test, run Cargo/nextest at its normal stable output path, reach Docker API and database under the selected policy. The Docker-child workaround in this PoC is insufficient evidence. Also prove the declared egress guarantee and explicit inner-Docker limitation/enforcement, plus current eject/exile/purge/hardline lifecycle and Jackin resource ownership. Policy hot-update connection survival is only a requirement if Jackin exposes live rule editing. Instant cleanup on test-process kill is not a current Jackin promise. Authenticated task is still a product acceptance test for readiness.

PoC workarounds are candidates, not inferred passes for a rewrite: separate output paths or Docker-executed tests, frozen policy, external fixture cleanup, and no inherited child policy each change behavior or ownership. A Jackin rewrite can preserve the user experience with different internals, but each claim requires runtime proof on the intended platform/backend. Existing PoC itself establishes only the tested OpenShell/OrbStack profile, not Docker Desktop, native Linux, remote gateway, Kubernetes, or full authenticated Architect operation.
