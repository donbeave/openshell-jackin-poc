# Gateway startup and mTLS evidence

Release v0.1.5 (`bdb956f2cd65a635f1294fccf1d138d263bf650f`); host macOS 27.0 arm64; Docker endpoint OrbStack Unix socket. This is gateway setup evidence, not sandbox runtime proof.

## Preliminary plaintext probe (retained)

Command used isolated `XDG_STATE_HOME` and `XDG_CONFIG_HOME` under `experiments/gateway`:

```sh
openshell-gateway --config experiments/gateway/gateway.toml --bind-address 127.0.0.1 --port 18770 --disable-tls --compute-driver docker
OPENSHELL_GATEWAY_ENDPOINT=http://127.0.0.1:18770 openshell status -o json
OPENSHELL_GATEWAY_ENDPOINT=http://127.0.0.1:18770 openshell sandbox list -o json
```

Result: **PASS** connectivity only. Gateway 0.1.5, Docker driver connected; empty sandbox list. Gateway logs warned `TLS disabled — listening on plaintext HTTP` and `the gateway has no authentication mechanism`. Process stopped before mTLS setup. Do not use this mode for any positive capability result.

## mTLS gateway

Config is in `experiments/gateway/gateway.toml`; launch command in `experiments/gateway/run-gateway.sh`. Release binary SHA-256 `60b562d2d78cab122bd998f14f6b5a22f1a20e4bb77943a25498caee8d041ec9`. Unique test PKI generated by:

```sh
openshell-gateway generate-certs --output-dir experiments/gateway/certs --server-san 127.0.0.1
openssl verify -CAfile experiments/gateway/certs/ca.crt experiments/gateway/certs/server/tls.crt experiments/gateway/certs/client/tls.crt
```

Expected and observed: both generated certs verify against test CA; exit 0. Client certificate subject uses `OU=openshell-user`. No certificate/private-key bytes saved in evidence.

First TLS startup failed, exit 1:

```text
configuration error: gateway TLS requires guest_tls_ca in [openshell.gateway] when using the docker compute driver
```

Added the generated CA as `guest_tls_ca`, required for Docker supervisor TLS. Same command then stayed live (PID `44804` at evidence capture). Logs: `TLS enabled — listening on encrypted HTTPS`; `TLS client certificate verification enabled`; `mTLS user authentication enabled`; `Compute driver connected configured_driver=docker advertised_driver=docker`; listener `127.0.0.1:18770`.

Registration used the isolated XDG dirs and generated test PKI:

```sh
OPENSHELL_LOCAL_TLS_DIR=experiments/gateway/certs XDG_CONFIG_HOME=experiments/gateway/config XDG_STATE_HOME=experiments/gateway/state openshell gateway add https://127.0.0.1:18770 --local --name ojp-20261024-gw
```

Result: exit 0; `Gateway 'ojp-20261024-gw' added and set as active`; endpoint `https://127.0.0.1:18770`; `TLS certificates present`. Active selection and copied mTLS material live only under experiment XDG dirs.

## Result classification

- Requirement: separate local gateway can run selected OpenShell release with Docker driver and mTLS.
- Result: **PASS**.
- Mechanism: **CONFIGURATION**.
- Ownership: manually launched gateway process, experiment-owned SQLite state, isolated CLI registration, and generated test PKI. OpenShell sandbox lifecycle has not yet been tested here.
- Limit: preliminary plaintext check does not prove secure auth. This setup is external to OpenShell lifecycle. Docker driver startup on OrbStack is proven; sandbox creation/stop/delete remain for parent experiments.
- Docker resource admission remains enabled. `allow_driver_config=true` allows nonempty Docker driver config only. External Docker volumes still need approved labels `openshell.ai/sandbox-attachable="true"` and `openshell.ai/sandbox-attachable-workspace="default"`. No host bind mounts enabled.

## Corrective setup after Docker launch denial

Parent recorded a real sandbox-create failure in `results/basic/create.json`: OpenShell returned `docker sandboxes require launch-scoped gateway authentication` (exit 1). The existing listener used mTLS user authentication, but had no sandbox-launch signing keys. This error is retained unchanged.

v0.1.5 documentation specifies a separate gateway JWT signing bundle. Added the release-supported `[openshell.gateway.gateway_jwt]` table to the isolated gateway config. It points to the existing experiment-owned files generated by `openshell-gateway generate-certs`: `jwt/signing.pem`, `jwt/public.pem`, and `jwt/kid`; gateway ID is `ojp-20261024`. `ttl_secs` omitted, matching documented local single-player Docker behavior. Listener mTLS remains enabled. Docker `allow_driver_config` and resource admission settings remain unchanged.

Reproduction/validation:

```sh
openshell-gateway config preflight --path experiments/gateway/gateway.toml
experiments/gateway/run-gateway.sh
experiments/gateway/client.sh status -o json
experiments/gateway/client.sh gateway info -o json
curl --fail --cacert experiments/gateway/certs/ca.crt --cert experiments/gateway/certs/client/tls.crt --key experiments/gateway/certs/client/tls.key https://127.0.0.1:18770/.well-known/jwks.json
```

Preflight exit 0. Gateway startup log: `gateway-minted sandbox JWT enabled gateway_id=ojp-20261024`; TLS and mTLS remain enabled; Docker driver connects. mTLS CLI health reports `connected`, auth `authenticated`, version `0.1.5`. Gateway info reports `healthy`, Docker `0.1.5`. JWKS returns Ed25519 public signing key metadata; public key value omitted here. No sandbox was created by this corrective subtask. Parent must rerun the original creation command to prove launch works.

- Requirement: Docker sandbox launch-scoped gateway auth is configured using released gateway config.
- Result: **PASS** configuration and signer publication; sandbox create awaiting parent rerun.
- Mechanism: **CONFIGURATION**.
- Scope: no security check disabled; no Jackin or OpenShell source patch. Listener client authentication stays mTLS. Signing key material remains under ignored experiment `certs/` with private mode 0600.

Source: [OpenShell v0.1.5 Gateway Configuration](https://docs.nvidia.com/openshell/v0.1.5/how-it-works/gateways/configuration), section `gateway_jwt`; listener TLS and sandbox launch signing use separate keys, and v0.1.5 local config uses `signing_key_path`, `public_key_path`, `kid_path`, and `gateway_id`.
