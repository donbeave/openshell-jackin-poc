**Source pin:** Jackin `6e266406b49da2ab3c55355f3b7d33d1643ee6cd` (immutable snapshot `experiments/full-refactor-20261024/source/jackin`, tree `11c7af3812dd9ba0be27f6ae33fc078fa40ff85c`). Source audit only: no product code changed and no row below is runtime PASS evidence.

**Scope:** Capsule process isolation and identity, session control/attach, account and credential staging, provider configuration, host actions/clipboard/export, usage transport, and actual agent launch support. Workflow verification workers and general Docker launch are audited by sibling workstreams. New design target is Candidate B: trusted Jackin control remains host-side; role/account domains use isolated OpenShell sandboxes, and generic shell authority uses a separate sandbox. Jackin keeps logical instance/session UX and authorization; OpenShell owns workload execution. This is a proposed boundary, not a proven integration.

## Candidate B challenge: session primitives that change

Candidate B avoids in-sandbox root account switching, but changes a core Capsule assumption: one local multiplexer owns the session table, shared tab/focus state, PTY children, event history, terminal size, and one attach socket. With a sandbox per account/agent, those objects are remote and separately owned. An OpenShell stream may supply process stdin/stdout, resize, and signal, but must not be presumed to provide Capsule’s persistent multi-session mux, event semantics, session ownership arbitration, or reconnect to an existing child.

Smallest safe runtime experiment: run two account-domain sandboxes and one shell sandbox; start two long-lived deterministic PTY programs (then one actual supported agent) through the proposed released Rust stream; disconnect and reconnect to the same sandbox/session identity; route focus/send/take-control/release-control and a signal to one session while verifying the other stays alive and receives no input; resize and observe exit status; restart one sandbox and distinguish session loss from client disconnect; then add a third role/agent target. Separately prove private home/config mounts remain distinct while only project mount is shared. If OpenShell cannot reconnect to an existing child or represent stable session identity, Candidate B needs a small Jackin-side session host/protocol adaptation or a supported OpenShell persistent-session operation. A helper sharing the agent UID cannot be cross-account or operator authority. This experiment is NOT TESTED and blocks readiness.

## Identity, credential, and behavior constraints for the rewrite

1. A sandbox is not an account domain unless Jackin creates a distinct private home/config mount and authorization record for it. Project data may be shared separately; private account state must not be shared with generic shell or another account.
2. Use immutable target identity + sandbox ID + runtime generation + session ID + account revision. Name-only lookup followed by mutation is unsafe against replacement races.
3. Account revision admission does not itself revoke already-established model, database, or Docker connections. The new product must define refresh/reconnect/revocation semantics and test the selected behavior rather than imply immediate termination.
4. Preserve agent-specific state/configuration. “API key”, profile synchronization, Claude OAuth, GitHub credentials, custom endpoint, model, effort, local MCP and remote MCP are distinct paths.
5. Host clipboard, URL opening, reveal-path, file export, keep-awake, and local terminal restoration belong to Jackin’s trusted host/client. Remote OpenShell workloads may request an action, but cannot perform it directly on a desktop.
6. Usage transport keeps Jackin provider/account policy. Transport success is not evidence that provider usage or billing is correct.

## Reuse and diff qualification

Historical runtime experiments under research commit `2315e6a...` and Jackin `41bad147...` are not blanket-compatible. Current Jackin is `6e266...`; Capsule changed substantially, in exactly 12 files (+5,889/-144): `pid1.rs`/tests, `main.rs`, `daemon/boot.rs`, `session/spawn.rs`/tests, `util.rs`, `pr_context.rs`, process telemetry, and Capsule manifest. `docker/runtime/entrypoint.sh` and `runtime_setup/agents.rs` are unchanged. Reuse an old experiment only for the same OpenShell release, driver, image/config, operation and code path after confirming the relevant code did not change. Darwin-specific reaping evidence requires Capsule actually running on macOS; a macOS host with a Linux VM/guest is not enough.

The following source-only points require live POCs and remain **NOT TESTED** here: real Capsule launch under OpenShell; candidate A and B account isolation; session protocol/stream semantics; host frame authorization; approved credential route; real model authentication for each admitted agent; account revision refresh/revoke; live shared workspace with separate home mounts; process tree cleanup/zombie behavior; usage relay over selected control transport. Source presence and unit tests cannot satisfy the research readiness gate.

## Disposition

This audit provides no runtime capability PASS. Candidate B is the least-conflicting architecture to test, but it requires a validated session transport and a concrete data/control mapping across multiple sandboxes. Until those and every admitted agent path have execution evidence on all required targets, the full OpenShell refactor remains **NOT READY** on this feature area.
